# Задание 2. «Создание заказа» — проверка API и обработки ошибок

**Пример запроса:**

```json
{
  "user_id": 15,
  "items": [
    {
      "product_id": 101,
      "quantity": 2
    }
  ]
}
```

> **Требование 1.** Для **создания заказа** необходимо передать `user_id` и непустой список `items`.
>
> **Требование 2.** Каждый товар должен содержать `product_id` и `quantity`.
>
> **Требование 3.** Количество товара `(quantity)` должно быть **положительным целым числом**.

> **Требование 6.** Если **товар не существует**, система возвращает *HTTP 404 Not Found*.

## 4. Проверка результата

HTTP-статуса мало. возьмем код 201 можно отдать, не создав заказ, создав заказ с другими полями. суть такова что статус говорит только то, что сервер решил ответить успехом. Он не доказывает, что в системе лежит нужная запись. Чтобы убедиться, что заказ создан корректно, после 201 нужно смотреть не тот же ответ, а повторное чтение заказа или запись в базе. В теле ответа должны быть идентификатор заказа и статус created. Это прямо требует требование 4. Ответ 201 без этих полей требование не выполняет.

По этому идентификатору должен лежать один заказ: user_id 15, товар 101, quantity 2, статус created. Так видно, что записали не другого пользователя и не проигнорировали количество. Число заказов пользователя должно вырасти на один, не на два и не остаться прежним. А так же повторное чтение через несколько секунд должно отдать те же поля. Статус сам не должен некуда уезжать, должен быть created. Этого перехода в требованиях нет.

Для ответов 400, 404, 409 и 503 та же проверка в обратную сторону: новой строки заказа нет. Иначе код ошибки совпадёт с требованием, а заказ всё равно появится.

## 6. Средняя сумма одного заказа по оплаченным заказам для каждого города

```sql
SELECT u.city, COALESCE(AVG(o.total), 0) AS avg
FROM users u
LEFT JOIN orders o ON u.id = o.user_id AND o.status = 'completed'
GROUP BY u.city;
```

По заданию видим что будем использовать агрегатные функции AVG значит используем группировку в конце. Селектим город и среднюю сумму. из таблицы пользователи. склеиваем таблицы по айди проверяем статус оплаченный и группируем по городу! это означает что наши суммы все прибавяться допустим если с одного города два заказа, то они прибавяться но мы ищем средние по этому с помощью авг мы возьмем не общую сумму а среднее по заказам.
